# Тестирование

## Уровни

| Уровень | Где | Запуск |
| ------- | --- | ------ |
| Движок — unit | `engine/tests` | `engine/.venv/Scripts/python -m pytest tests/ -q` |
| Backend | `backend/tests` | `make test-back` |
| Frontend | `frontend` | `make test-front` |
| Линт и типы | обе части | `make lint`, `mypy` |

## Регресс-проверка результата

Для движка обычных тестов недостаточно: код может быть исправен, а картинка
испорчена. Поэтому основной регресс-механизм — **матрица изображений**, которую
даёт текущий срез ([Roadmap-MVP, шаг S7](../base-plans/Roadmap-MVP.md#7-шаги)):
фиксированный набор сцен, ракурсов и настроек прогоняется одной командой, и
любое утолщение системы обязано её не сломать.

Проверяется в матрице:

- герой в финальном кадре совпадает с собственным рендером (силуэт, черты);
- воспроизводимость — тот же конфиг и сид дают тот же кадр;
- счёт объектов и отсутствие лишних конечностей;
- связность героя и фона.

## Правила

- **Каждый шаг среза закрывается своей «Проверкой ✅»** — сформулированной до
  начала работы, а не подогнанной под результат. Формулировки — в
  [Roadmap-MVP](../base-plans/Roadmap-MVP.md).
- **Числа, а не впечатления.** Результат гейта идёт в
  [журнал решений](../base-plans/decision-log.md) с измерениями.
- **Человеческая оценка легитимна там, где автоматической метрики нет** —
  например, «читается ли стиль». Но это должно быть заявлено явно, а не выдано
  за метрику.

## Шаблон баг-репорта

```
Заголовок:
Окружение / версия (коммит, конфиг, сид):
Шаги воспроизведения:
Ожидаемый результат:
Фактический результат:
Серьёзность / приоритет:
```

Для дефектов изображения обязательно прикладывать конфиг и сид — без них
воспроизвести нельзя.
