# ADR 0001: Ведение архитектурных решений через ADR

- **Статус:** принято
- **Дата:** 2026-07-25

## Контекст

Нужен лёгкий, версионируемый способ фиксировать значимые архитектурные решения
и причины их принятия, чтобы новые участники понимали контекст.

## Решение

Каждое значимое решение оформляется отдельным файлом `NNNN-краткое-название.md`
в `docs/architects/adr/`. Формат: Контекст → Решение → Последствия. Статусы:
предложено / принято / отклонено / устарело / заменено ADR-XXXX.

## Последствия

- Плюс: прозрачная история решений, живёт рядом с кодом в git.
- Минус: требует дисциплины — ADR нужно писать в момент принятия решения.
