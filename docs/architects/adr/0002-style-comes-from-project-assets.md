# ADR 0002: Стилизация определяется ассетами проекта, а не генератором

- **Статус:** принято
- **Дата:** 2026-08-13
- **Связано:** [Roadmap, раздел 7](../../base-plans/Roadmap.md#7-рендер-стили-борьба-с-галлюцинациями),
  [Roadmap MVP](../../base-plans/Roadmap-MVP.md)

## Контекст

Требование продукта — выдавать сцены в разных визуальных стилях (аниме, манхва,
кино, гиперреализм). Рассматривались два способа его выполнить.

**Вариант A — стиль накладывает генератор.** В базе один канонический 3D-ассет
персонажа, генератор перерисовывает его в нужный стиль. Упирается в две
проблемы, каждая из которых критична:

- *Пропорции.* Аниме-персонаж геометрически отличается от фотореалистичного
  (голова, глаза, сложение). Чтобы получить аниме из реалистичного ассета,
  генератор должен изменить пропорции — то есть получить ровно ту свободу,
  которая ломает геометрический замок идентичности. Без изменения пропорций
  выходит «реалистичный рендер с тун-шейдером», а не аниме.
- *Идентичность.* Чем длиннее поводок, нужный для стиля, тем меньше остаётся
  гарантий, что в кадре тот же самый персонаж. Гиперреализм и манхва требуют
  противоположных положений одного и того же регулятора.

**Вариант B — стиль приходит из ассетов проекта.** Пользователь загружает
референсы персонажа с разных ракурсов, по ним строится модель — уже в целевом
стиле. Стиль есть свойство проекта, а не переключатель на объекте.

## Решение

Принимается вариант B.

- **Стиль — свойство проекта.** Проект несёт профиль стиля; ассеты проекта
  авторятся или реконструируются в этом стиле.
- **Герои не перестилизовываются.** Персонажи и сюжетно значимые объекты
  приходят из базы проекта и **рендерятся**, а не перерисовываются генератором.
- **Зона ответственности генератора** — сеттинг, окружение, фоновые объекты,
  свет, атмосфера и доводка кадра. То есть всё, у чего нет отслеживаемой
  идентичности.
- **Профиль стиля управляет обоими концами**: параметрами рендера героев
  (шейдер, контур, палитра) и настройкой генератора для фона (LoRA, промпт,
  длина поводка). Один источник правды, два потребителя.
- **Поводок пространственно неоднороден**: короткий на героях (защищены
  масками инстансов), длинный на фоне.

## Последствия

**Плюсы:**

- Проблема пропорций растворяется — ассет изначально в целевом стиле.
- Идентичность сквозь стилизацию перестаёт быть риском: героя никто не
  перерисовывает, идентичность держится по построению.
- Стилевые варианты ассета в базе не нужны — снимается кратное удорожание
  подготовки контента.
- Свобода генератора оказывается там, где она безопасна и полезна: фон,
  атмосфера, красота кадра.
- Совпадает с реальным производством: у проекта есть облик, один герой не
  ходит между стилевыми семействами.

**Минусы и новые обязательства:**

- **NPR-рендер становится обязательным**, а не опциональным: раз стиль приходит
  из ассета, рендерер обязан уметь его показать (плоская заливка, контуры,
  палитра).
- **Появляется задача связности героя и фона.** Рендер героя и генерация фона
  должны читаться как один мир; за это отвечает профиль стиля, и это новый
  основной риск вместо снятых.
- **Требуется механизм пространственно неоднородного поводка** (локальная сила
  денойза по маскам инстансов).
- **Смена стиля внутри проекта — это переавторинг ассетов**, а не переключатель.
  Осознанный размен: гибкость обменяна на гарантии.
- **Стили, жульничающие с геометрией** (аниме-причёска, лицо не в перспективе,
  глаза одинакового размера с любого ракурса), не сводятся в одну 3D-модель из
  противоречащих видов. Для таких случаев нужен либо приём «3D-версии»
  персонажа, либо гибрид: 3D держит композицию и позу, генератор перерисовывает
  лицо. Решение по этому случаю отложено.
