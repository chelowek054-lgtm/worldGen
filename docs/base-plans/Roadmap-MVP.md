# Roadmap MVP — первый сквозной срез

Тонкая полоска через все слои системы: один подготовленный 3D-персонаж →
рендер → генератор → красивая картинка в четырёх стилях, с сохранением
идентичности. Каждый слой реализован грубо; цель — не функциональность, а
**информация**: работает ли посылка продукта вообще.

- **Создан:** 2026-08-13
- **Контекст:** принцип из [Roadmap, раздел 15](Roadmap.md#15-предлагаемая-последовательность).
  Общее состояние решений — в [Roadmap.md](Roadmap.md).
- **Формат выхода:** только изображения. Видео вне рамок MVP.

---

## 1. Гипотеза, которую проверяем

> Сцена, собранная из наших ассетов и перерисованная по стилевому референсу
> пользователя, сохраняет узнаваемость персонажа между ракурсами и между
> стилями — при этом кадр красивый.

Постановка следует из [ADR 0002](../architects/adr/0002-style-comes-from-project-assets.md):
содержание наше, облик выбирает пользователь и он применяется перерисовкой
финального рендера. Главный проверяемый риск — **устойчивость идентичности при
перерисовке**.

Риск смягчён конструкцией, и это надо использовать: геометрия и композиция во
всех кадрах одинаковы (тот же ассет, тот же рендер), стилевой референс один на
проект, сид фиксирован. Перерисовка — почти детерминированная функция неизменных
входов. Если при таких условиях персонаж всё равно плывёт, мы узнаём это за две
недели и остаются варианты: укоротить поводок на герое, усилить структурные
условия, добавить герою собственный якорь идентичности.

## 2. Ключевое: срез не блокируется решением 2.5

Открытое решение [2.5](Roadmap.md#2-представление-объекта-днк) (на чём базируем
структурированный латент) **не мешает начать**. MVP берёт готовый меш и обычный
рендер G-буфера — ни структурированные латенты, ни гауссианы, ни декодер здесь
не нужны.

Это сознательный размен: срез проверяет **риск на стороне генератора**, который
и есть главный продуктовый риск, не коммитясь к представлению объекта. Если
идентичность не переживёт стилизацию, вопрос о формате латента станет
неважным — падать будет нечему.

## 3. Что специально НЕ входит

| Не входит | Почему отложено |
| --------- | --------------- |
| Физика, разрушение, падение | Отдельный крупный риск; сценарий с посохом ломается от отсутствия персистентности раньше, чем от неточной физики. |
| Риг и смена позы | Ассет берём в одной готовой позе. Артикуляция — следующее утолщение. |
| Реестр ассетов, retrieval | Папка с одним файлом. |
| Парсинг промпта в граф сцены | JSON пишем руками. |
| Версионирование сцены, ветки | Не нужно, чтобы проверить гипотезу. |
| Структурированный латент, 3DGS | См. раздел 2. |
| Видео, темпоральная консистентность | Формат MVP — изображения. |
| Веб-сервис, очередь, UI | Скрипты и конфиги. |

## 4. Минимальный состав

### 4.1 Ассет — один персонаж, плюс стилевые референсы

Один готовый 3D-персонаж нейтрального облика (не привязанный к конкретной
стилистике) и **два-три стилевых референса** — картинки, задающие облик, как их
принёс бы пользователь.

Ассет один, потому что после ADR 0002 контент от стиля не зависит: проверяем
именно то, что одна и та же модель отдаётся в разных обликах и остаётся собой.

Реконструкция из пользовательских загрузок и генерация ассетов в срез **не
входят** — берём готовую модель. Это отдельные риски, мешать их с проверяемым
здесь нельзя.

### 4.2 Сцена

JSON руками: ссылка на ассет, камера (позиция, поворот, FOV), источники света.
Плюс простое окружение (земля, задник) — чтобы это была сцена, а не вырезанный
персонаж на сером фоне.

**Свет входит в MVP обязательно.** Если осветить плоско, мы получим скучные
картинки и сделаем неверный вывод «пайплайн выдаёт некрасиво», хотя на самом деле
мы просто плохо поставили свет. Минимум одна осмысленная световая схема.

### 4.3 Рендер G-буфера

Из обычного 3D-рендерера, набором проходов:

- глубина
- нормали
- маски инстансов по ID
- цвет (базовый рендер со светом)
- силуэт / контурные линии — понадобятся для стилизованных режимов

Плюс тот же кадр как быстрое превью (без генератора) — это уже второй тир
рендера из большой схемы, в зачаточном виде.

### 4.4 Профиль стиля — основная настраиваемая сущность

Один объект конфигурации на проект, управляющий **обоими концами** сразу:

| Что задаёт | Для рендера героев | Для генерации фона |
| ---------- | ------------------ | ------------------ |
| Подача | шейдер (плоский/PBR), толщина контура | стилевая LoRA либо промпт |
| Цвет | палитра, ограничение градаций | палитра как ограничение |
| Свобода | — (герой защищён маской) | длина поводка на фоне |

Профиль стиля — это и есть проверяемый механизм. Если для рисованного и
фотореалистичного проектов достаточно поменять профиль, не трогая код, механизм
состоялся.

**Поводок пространственно неоднороден:** короткий на героях (по маскам
инстансов), длинный на фоне. Это ключевая техника среза — без неё генератор либо
испортит героя, либо не сможет сделать фон интересным.

Стилевые LoRA на старте берём готовые, не обучаем — обучение своих это
отдельная работа, и до неё надо убедиться, что механизм в принципе жив.

### 4.5 Генератор

Диффузионный генератор в режиме img2img поверх рендера (не из шума), с
ControlNet-условиями по G-буферу. Выбор конкретной модели —
[Roadmap 7.11](Roadmap.md#7-рендер-стили-борьба-с-галлюцинациями); для MVP
критично только, чтобы лицензия допускала коммерческое использование.

### 4.6 Проверка

- **Счёт объектов и силуэт** — сошлось ли то, что в кадре, с тем, что в сцене.
- **Идентичность** — см. раздел 6, метрика частично открыта.
- Прогон всей матрицы одной командой, результаты в трекинг (`MLflow` уже есть).

## 5. Матрица эксперимента

|  | Фас | Три четверти | Профиль |
| --- | --- | --- | --- |
| Стилевой референс A | ● | ● | ● |
| Стилевой референс B | ● | ● | ● |

Шесть изображений с одного ассета. По строкам — идентичность между ракурсами
внутри одного облика (легче). По столбцам — узнаваемость одного персонажа между
обликами (тяжелее, это и есть настоящий тест). Плюс в каждой ячейке проверяется,
что фон и герой читаются как один мир.

## 6. Критерии успеха

| Критерий | Как меряем | Порог |
| -------- | ---------- | ----- |
| **Герой пережил перерисовку** | сравнение с чистым рендером: силуэт, черты, пропорции | без грубых расхождений |
| Идентичность между ракурсами | человеческая оценка «тот же персонаж?» внутри строки | ни одной неузнаваемой ячейки |
| Идентичность между обликами | то же по столбцам | персонаж узнаётся в обоих |
| Воспроизводимость | тот же конфиг и сид → тот же кадр | совпадение |
| Связность героя и фона | «один мир или коллаж?» | ни одной ячейки-коллажа |
| Отсутствие галлюцинаций | счёт объектов, лишние конечности | ноль грубых нарушений |
| Красота | субъективная оценка | картинку не стыдно показать |

Метрика идентичности здесь проще, чем через «стилевую пропасть»: сравнивается
рендер героя с ним же в финальном кадре того же облика — это измеримо
автоматически. Сравнение между обликами остаётся человеческим.

## 7. Главный исследовательский вопрос MVP

> Какая длина поводка на герое даёт одновременно читаемый стиль и сохранённую
> идентичность — и существует ли вообще такое окно?

Если окно широкое, всё дальнейшее строится спокойно. Если узкое, понадобится
якорь идентичности на герое сверх структурных условий. Если окна нет — это
центральный результат среза, и он разворачивает продукт обратно к варианту A из
[ADR 0002](../architects/adr/0002-style-comes-from-project-assets.md).

## 8. Шаги

Каждый шаг имеет проверку; следующий не начинается, пока предыдущий не закрыт.

### S0 · Подготовить ассет и сцену `[ ]`
Один персонаж нейтрального облика в одной позе, простое окружение, осмысленная
световая схема. Плюс два-три стилевых референса.
**Проверка ✅:** сцена рендерится и выглядит прилично **без всякого генератора**.

### S1 · Рендер G-буфера `[ ]`
Скрипт: сцена (JSON) → проходы (глубина, нормали, маски инстансов, цвет, контуры).
**Проверка ✅:** три ракурса, проходы согласованы; **маски чистые на границах** — грязная маска ломает весь контрольный стек дальше.

### S2 · Сквозная цепочка, короткий поводок везде `[ ]`
Один ракурс, один стилевой референс, генератор доводит кадр слабо.
**Проверка ✅:** на выходе изображение, персонаж не испорчен относительно рендера; повтор с тем же сидом даёт тот же кадр.
**Если не прошло:** дело не в стиле, а в базовой связке — разбираться с условиями и силой денойза, дальше не идти.

### S3 · Найти окно поводка на герое `[ ]`
Прогнать шкалу силы перерисовки на герое: от почти нетронутого до полностью
перерисованного. Найти диапазон, где стиль уже читается, а персонаж ещё узнаётся.
**Проверка ✅ (гейт MVP):** такое окно существует и достаточно широкое, чтобы им пользоваться.
**Если не прошло:** центральный результат среза. Развилки: добавить герою якорь идентичности сверх структурных условий; усилить контрольный стек; в крайнем случае — вернуться к варианту A из ADR 0002 (стиль в ассете).

### S4 · Пространственно неоднородный поводок `[ ]`
Развести маской: фон получает свободу, герой держится в найденном окне.
**Проверка ✅:** фон заметно интереснее, герой не поехал, кадр читается как один мир, а не коллаж.

### S5 · Второй стилевой референс и три ракурса `[ ]`
Заполнить матрицу целиком, меняя **только референс и камеру**.
**Проверка ✅:** персонаж узнаётся во всех шести ячейках; код между обликами не правился.
**Если не прошло:** часть стиля осела в коде — вынести в профиль.

### S6 · Второй объект в кадре `[ ]`
Добавить второй identity-несущий ассет рядом с персонажем.
**Проверка ✅:** атрибуты не перетекают — текстура одного объекта не оказывается на другом; оба узнаваемы.
**Если не прошло:** усиливать маскирование по инстансам.

### S7 · Собрать в воспроизводимый прогон `[ ]`
Одна команда → вся матрица → изображения и метрики в трекинг.
**Проверка ✅:** повторный прогон того же конфига даёт тот же результат; матрица становится регресс-набором для всех последующих утолщений.

## 9. Открытые вопросы внутри MVP

| Вопрос | Почему важен |
| ------ | ------------ |
| Чем анкерить героя, если окно поводка окажется узким | Структурных условий может не хватить; вариант — референс самого персонажа в дополнение к стилевому. |
| Готовые стилевые LoRA или только IP-Adapter по референсу | Референс пользователя — обязателен; LoRA как усиление пресетов, но тянет собственную эстетику. |
| Как чисто получить маски инстансов на границах | Грязная маска ломает и защиту героя, и неоднородный поводок. |
| Насколько жёстко связывать палитру фона с палитрой рендера | Слабо — коллаж; жёстко — фон скучный. |
| Сколько ракурсов достаточно | Три — минимум; крайние (сверху, со спины) могут ломаться раньше. |

## 10. Что дальше, после среза

Утолщать по данным, а не по плану: следующим делается тот слой, который
оказался слабым звеном для нужной возможности. Наиболее вероятный порядок —
второй персонаж и реестр ассетов, затем поза и риг, затем хранилище сцены с
инкрементальными правками, и только потом физика. Матрица из S7 остаётся
регресс-набором: каждое утолщение обязано её не сломать.
