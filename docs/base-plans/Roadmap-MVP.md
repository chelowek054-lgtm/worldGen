# Roadmap MVP — первый сквозной срез

Тонкая полоска через все слои системы: один стилизованный персонаж → сборка
сцены → cel-рендер с пассами → перерисовка по стилевому референсу → изображение.
Каждый слой реализован грубо; цель — не функциональность, а **информация**:
работает ли посылка продукта вообще.

- **Создан:** 2026-08-13 · **Обновлён:** 2026-08-16
- **Контекст:** принцип из [Roadmap, раздел 15](Roadmap.md#15-предлагаемая-последовательность);
  граница ответственности — [ADR 0002](../architects/adr/0002-style-comes-from-project-assets.md);
  разбор стоимости — [Roadmap, раздел 17](Roadmap.md#17-критический-разбор-вычисления-против-консистентности).
- **Формат выхода:** только изображения.

---

## 1. Решения, зафиксированные под MVP

| Решение | Значение | Почему |
| ------- | -------- | ------ |
| 3D-стек | **Blender**, headless, через Python | Cryptomatte, Z/normal-пассы и композитор уже есть — не строим то, что готово. Blender всё равно нужен для подготовки ассета. |
| Формат сцены | JSON под наши нужды, ассеты — glTF | USD как формат сцены оставлен на потом: для одной сцены его композиция избыточна. |
| Рендерер | **EEVEE** | Cel-шейдинг не нуждается в путьтрейсинге; EEVEE даёт и базу, и превью. |
| Стилевая плоскость | **одна — стилизованная (cel/аниме)** | Бьём в риск: длинный поводок против идентичности. |
| Генератор | диффузия в img2img + структурные условия + стилевой референс | Облик пользовательский ([ADR 0002](../architects/adr/0002-style-comes-from-project-assets.md)). |
| Физика | **не входит** | Дорого и решает другую ось ([17.2](Roadmap.md#172-физика--самый-дорогой-компонент-не-решающий-нашу-задачу)). |

**Godot** рассмотрен и отложен осознанно: он лучше как рантайм прода (MIT,
лёгкий процесс, миллисекунды на кадр), но требует самому написать ID-пасс,
нормали и детект краёв. Возвращаемся к нему по триггеру: упёрлись в пропускную
способность рендера **или** захотели интерактивное превью в браузере. Чтобы
смена осталась дешёвой, **сцена описывается данными, а рендерер их потребляет** —
никакой логики сцены внутри рендер-скрипта.

## 2. Гипотеза

> Существует такая длина поводка генератора, при которой стиль уже читается как
> аниме, а персонаж ещё узнаётся как тот же самый между ракурсами.

Это и есть главный вопрос среза. Если окно широкое — дальше всё строится
спокойно. Если узкое — понадобится якорь идентичности сверх структурных условий.
Если окна нет — это центральный результат, разворачивающий продукт обратно к
варианту A из [ADR 0002](../architects/adr/0002-style-comes-from-project-assets.md)
(стиль в ассете, героя не перерисовываем).

Риск смягчён конструкцией, и это надо использовать: геометрия во всех кадрах
одна и та же, стилевой референс один, сид фиксирован — перерисовка почти
детерминирована.

## 3. Что специально НЕ входит

| Не входит | Почему отложено |
| --------- | --------------- |
| Физика, разрушение, падение | Отдельный крупный риск, другая ось, дорого. |
| Смена позы, анимация | Ассет в одной готовой позе. |
| Реестр ассетов, поиск, генерация ассетов | Папка с одним файлом. |
| Парсинг промпта в граф сцены | JSON пишем руками. |
| Версионирование сцены, ветки | Не нужно для проверки гипотезы. |
| Вторая стилевая плоскость | Одна плоскость, но исследуем в ней весь диапазон поводка. |
| Веб-сервис, очередь, UI | Скрипты и конфиги. |

## 4. Минимальный состав

### 4.1 Ассет

Один готовый стилизованный персонаж с ригом (glTF), в одной позе.

**Важно при выборе:** нужен персонаж, стилизованный, но **геометрически
честный** — то есть cel-модель уровня игрового или VTuber-персонажа, а не
попытка воспроизвести нарисованное аниме-лицо. Стили, жульничающие с геометрией
(лицо не в перспективе, глаза одного размера с любого ракурса), приняты как
ограничение в [ADR 0002](../architects/adr/0002-style-comes-from-project-assets.md#последствия)
и в срез не берутся.

Плюс простое окружение (земля, задник) и **осмысленная световая схема** — если
осветить плоско, получим скучные кадры и сделаем ложный вывод «пайплайн
некрасив».

### 4.2 Описание сцены

JSON руками: ссылка на ассет, камера (позиция, поворот, FOV), свет, профиль
стиля. Рендер-скрипт читает его и ничего не решает сам — вся логика сцены
снаружи, чтобы рендерер оставался заменяемым (см. 1).

### 4.3 Рендер и пассы

Один прогон Blender выдаёт:

| Выход | Как получаем | Зачем |
| ----- | ------------ | ----- |
| Cel-база | EEVEE + Shader-to-RGB с ступенчатым градиентом | стартовая точка для перерисовки |
| Контуры | inverted hull (Solidify с вывернутыми нормалями) + детект краёв по глубине и нормалям в композиторе | линия — половина стиля |
| Глубина | Z-пасс | структурное условие |
| Нормали | Normal-пасс | структурное условие |
| Маски инстансов | **Cryptomatte Object** | защита героя, неоднородный поводок |

Всё в один многослойный EXR. Cryptomatte здесь закрывает вопрос, который в
прошлой редакции стоял открытым («чистые маски на границах») — это его штатное
назначение.

### 4.4 Профиль стиля

Один объект конфигурации, управляющий обоими концами:

| Задаёт | Для рендера | Для генератора |
| ------ | ----------- | -------------- |
| Подача | число ступеней тона, толщина контура | стилевой референс |
| Цвет | палитра | палитра как ограничение |
| Свобода | — | длина поводка, раздельно для героя и фона |

### 4.5 Генератор

Диффузия в режиме img2img поверх cel-базы (не из шума), со структурными
условиями из 4.3 и стилевым референсом. Обязательны: фиксированный сид и
раздельная сила перерисовки по маске героя и по фону.

### 4.6 Проверка

- Сравнение героя в финальном кадре с чистым cel-рендером (силуэт, черты).
- Счёт объектов, отсутствие лишних конечностей.
- Повтор с тем же конфигом и сидом даёт тот же кадр.
- Прогон всей матрицы одной командой, метрики и картинки — в MLflow.

## 5. Матрица

|  | Фас | Три четверти | Профиль |
| --- | --- | --- | --- |
| Поводок короткий | ● | ● | ● |
| Поводок средний | ● | ● | ● |
| Поводок длинный | ● | ● | ● |

Девять изображений с одного ассета в одной стилевой плоскости. По строкам —
идентичность между ракурсами при фиксированной свободе. По столбцам — как
идентичность и стиль расходятся при росте свободы. Пересечение и даёт искомое
окно.

## 6. Критерии успеха

| Критерий | Как меряем | Порог |
| -------- | ---------- | ----- |
| **Окно поводка существует** | есть строка, где стиль читается и герой узнаётся | хотя бы одна |
| Герой пережил перерисовку | сравнение с cel-рендером | без грубых расхождений силуэта и черт |
| Идентичность между ракурсами | человеческая оценка внутри строки | ни одной неузнаваемой ячейки |
| Стиль читается | человеческая оценка «это аниме?» | без подсказки |
| Воспроизводимость | тот же конфиг и сид → тот же кадр | совпадение |
| Связность героя и фона | «один мир или коллаж?» | ни одной ячейки-коллажа |
| Красота | субъективная оценка | картинку не стыдно показать |

Метрика идентичности тут измерима автоматически: сравнивается герой с
собственным cel-рендером того же кадра, а не через стилевую пропасть.

## 7. Шаги

### S0 · Ассет и сцена `[~]`
Найти и привести в порядок cel-персонажа с ригом, собрать окружение и свет,
описать сцену в JSON.
**Проверка ✅:** сцена рендерится в Blender и выглядит прилично **без всякого генератора**.

**Сделано:** схема сцены и профиль стиля (`worldgen/scene/`, `worldgen/style/`),
запуск Blender подпроцессом (`worldgen/render/`), конфиги
[`configs/mvp/`](../../engine/configs/mvp/), команда `scripts/render_scene.py`.
Сцена собрана и рендерится в трёх ракурсах на **Blender 5.1.1** headless — свет,
кадрирование и азимуты проверены. Воспроизводимость рендерной половины цепочки
проверена: два прогона одного конфига дают побайтово одинаковый PNG (нестабильные
штампы метаданных отключены в рендер-скрипте).

**Осталось:** настоящий герой. Проверка сейчас прогнана на болванке
(`configs/mvp/scene.proxy.json`), а она отвечает только за свет и кадр — «выглядит
прилично» без cel-персонажа не засчитывается. Шаг закрывается, когда в
`data/assets/hero.glb` ляжет модель и три ракурса на ней будут выглядеть прилично.

### S1 · Рендер-скрипт и пассы `[ ]`
Headless Blender: JSON → cel-база, контуры, глубина, нормали, cryptomatte.
Каркас запуска и разбор описания сцены уже есть от S0 — добавляется cel-шейдинг,
контуры и вывод пассов в multilayer EXR.
**Проверка ✅:** три ракурса, все пассы согласованы; маски инстансов чистые на границах.
**Если не прошло:** без чистых масок дальше нельзя — чинить здесь, к генератору не переходить.

### S2 · Сквозная цепочка `[ ]`
Один ракурс, короткий поводок, генератор слегка доводит кадр.
**Проверка ✅:** изображение получено, герой не испорчен, повтор с тем же сидом даёт тот же кадр.
**Если не прошло:** дело в базовой связке — разбираться с условиями и силой денойза.

### S3 · Шкала поводка — гейт MVP `[ ]`
Прогнать три уровня свободы на одном ракурсе.
**Проверка ✅ (гейт):** существует уровень, где стиль читается и герой узнаётся.
**Если не прошло:** центральный результат среза. Развилки: якорь идентичности на герое сверх структурных условий; усиление контрольного стека; в крайнем случае возврат к варианту A из ADR 0002.

### S4 · Неоднородный поводок `[ ]`
Развести по маске: фон свободнее, герой держится в найденном окне.
**Проверка ✅:** фон заметно интереснее, герой не поехал, кадр читается как один мир.

### S5 · Полная матрица `[ ]`
Три ракурса × три уровня свободы.
**Проверка ✅:** девять ячеек собраны, окно подтверждается на всех ракурсах.

### S6 · Второй объект `[ ]`
Добавить второй identity-несущий ассет рядом с персонажем.
**Проверка ✅:** атрибуты не перетекают, оба узнаваемы.

### S7 · Воспроизводимый прогон `[ ]`
Одна команда → вся матрица → картинки и метрики в трекинг.
**Проверка ✅:** повтор даёт тот же результат; матрица становится регресс-набором для последующих утолщений.

## 8. Где это живёт в коде

```
engine/
  worldgen/
    scene/          # схема JSON сцены, валидация — рендерер её не знает
    style/          # профиль стиля, длины поводка
    render/         # запуск Blender подпроцессом, разбор EXR-пассов
      blender/      # скрипты, исполняемые внутри Blender (bpy)
    repaint/        # генератор: условия, маски, сид
  scripts/
    render_scene.py # сцена → пассы
    run_matrix.py   # вся матрица → трекинг
  configs/
    mvp/            # сцена, профиль стиля, шкала поводка
```

`bpy` доступен только внутри процесса Blender, поэтому скрипты в
`render/blender/` запускаются подпроцессом и не импортируются пакетом
`worldgen` напрямую.

## 9. Открытые вопросы внутри MVP

| Вопрос | Почему важен |
| ------ | ------------ |
| Чем анкерить героя, если окно окажется узким | Структурных условий может не хватить; вариант — референс самого персонажа вдобавок к стилевому. |
| Контур: inverted hull или композитный детект краёв | Первый стабильнее и дешевле, второй гибче; возможно нужны оба. |
| Насколько жёстко связывать палитру фона с палитрой рендера | Слабо — коллаж; жёстко — фон скучный. |
| Сколько ступеней тона в cel-базе | Влияет и на читаемость стиля, и на то, за что цепляется генератор. |
| Сколько ракурсов достаточно | Три — минимум; крайние (сверху, со спины) могут ломаться раньше. |

## 10. Что дальше

Утолщать по данным, а не по плану. Наиболее вероятный порядок: реестр ассетов и
второй персонаж → поза и риг → парсинг промпта в граф сцены → хранилище сцены с
инкрементальными правками → вторая стилевая плоскость → физика (опционально, по
[17.2](Roadmap.md#172-физика--самый-дорогой-компонент-не-решающий-нашу-задачу)).
Матрица из S7 остаётся регресс-набором: каждое утолщение обязано её не сломать.
