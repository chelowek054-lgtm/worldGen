## Фаза 0 — База и метрики `[~]`

> Гейт фазы: метрики (A и B) воспроизводимы (±2%) и задокументированы; виден измеримый зазор бейзлайна.

| ID | Задача | Статус |
| -- | ------ | ------ |
| 0.0 | Definition of Ready: каркас `engine/`, фикс seed, Hydra-конфиги, трекинг (MLflow), DVC, `reproduce.py` | `[x]` |
| 0.1 | Собрать оценочный «золотой набор» (20–50 объектов ×8 видов; 10–15 сцен; 5–10 физ-сюжетов; read-only + DVC) | `[~]` |
| 0.1a | ↳ Инструментарий: perceptual-hash, overlap-check, манифест + set_hash | `[x]` |
| 0.1b | ↳ Наполнение данными (источник) + `dvc add` + фикс хеша | `[ ]` |
| 0.2 | Метрики оси A: `DINO`-косинус + `CLIP-I`; темпоральная (`RAFT` warp-error, CLIP f2f); предохранители (`FID`/`FDD`, `CLIPScore`) | `[ ]` |
| 0.3 | Бенчмарки оси B: `PhyWorldBench` / `T2VPhysBench` / `Physion-Eval` + 3–5 собственных физ-чеков | `[ ]` |
| 0.4 | Бейзлайны «из коробки»: фото (`IP-Adapter`/`InstantID`), видео (`LTX-Video`) → таблица `baseline_v0` | `[ ]` |
| 0.G | 🚦 Go/No-Go фазы 0 | `[ ]` |

## Фаза 1 — View-invariant «ДНК» одного объекта `[~]`

> Гейт фазы: ДНК-консистентность заметно выше `IP-Adapter` без регрессий по FID/промпту.
> Открыта опережающе, до `0.G` — см. [decision-log](decision-log.md).

| ID | Задача | Статус |
| -- | ------ | ------ |
| 1.1 | Мультивид-данные для инвариантности (Objaverse-рендеры, `CO3D`/`MVImgNet`, позитивы/негативы) | `[ ]` |
| 1.2 | ДНК-компрессор поверх замороженного `DINOv3` (Slot Attention / Perceiver, N=4…16 токенов, контрастив) | `[~]` |
| 1.2a | ↳ Каркас: `engine/worldgen/dna/` (бэкбон/компрессор/лоссы/датасет/трейнер/предиктор/чекпоинты), обучение на синтетике | `[x]` |
| 1.2b | ↳ Обучение на реальном `DINOv3` + реальных мультивид-данных (ждёт 1.1) | `[ ]` |
| 1.3 | Инъекция ДНК в замороженный генератор (IP-Adapter-стиль K/V/out, подбор λ) | `[ ]` |
| 1.4 | Сравнение с бейзлайном и абляции (текст / IP-Adapter / ДНК; с-без контрастива; N токенов) | `[ ]` |
| 1.G | 🚦 Go/No-Go фазы 1 | `[ ]` |

## Фаза 2 — Мультиассетная сцена + retrieval `[ ]`

> Гейт фазы: сцена из K объектов без утечки идентичности; добавление ассета без обучения.

| ID | Задача | Статус |
| -- | ------ | ------ |
| 2.1 | Раскладка сцены как условие (боксы/граф отношений, регионально-маскированное внимание, GLIGEN-стиль) | `[ ]` |
| 2.2 | Композиция K ДНК без утечки (2→K с масками, тюнинг адаптера раскладки, рост K) | `[ ]` |
| 2.3 | Retrieval-банк ассетов (`FAISS`: ID → ДНК, обусловливание без дообучения) | `[ ]` |
| 2.4 | Регресс-прогон фото-пайплайна (нет регресса на одиночных, лучше бейзлайна на мультиобъектных) | `[ ]` |
| 2.G | 🚦 Go/No-Go фазы 2 | `[ ]` |

## Фаза 3 — Персистентное 3D-нативное состояние `[ ]`

> Гейт фазы: виды сходятся к одному объекту; переход фото→видео держит идентичность; построение состояния — feed-forward.

| ID | Задача | Статус |
| -- | ------ | ------ |
| 3.1 | Feed-forward построение состояния (`AnySplat`/`LRM`/`TriplaneGaussian`/`FluSplat`, без пер-сценовой оптимизации) | `[ ]` |
| 3.2 | Рендер произвольного вида/кадра (сплат-рендер или обусловленный генератор; орбита камеры) | `[ ]` |
| 3.3 | Темпоральная согласованность (фикс состояния, меняем камеру → клип; warp-error, CLIP f2f) | `[ ]` |
| 3.4 | Мультиобъектная сцена в состоянии (общая камера/свет, корректные окклюзии/глубины) | `[ ]` |
| 3.G | 🚦 Go/No-Go фазы 3 | `[ ]` |

## Фаза 4 — Латентный физдвижок `[ ]`

> Гейт фазы: совпадение с солвером в пределах ε, ≥10× скорости, обобщение на новые конфиги, физ-скор ≥ бейзлайнов.

| ID | Задача | Статус |
| -- | ------ | ------ |
| 4.1 | Данные-учитель из солвера (`Genesis`-роллауты и/или `PhysX`-логи из UE5; сопоставление с узлами графа) | `[ ]` |
| 4.2 | Латентный переход `fθ` (граф + message passing GNS-стиль, эквивариантность/сохранения, pushforward-noise) | `[ ]` |
| 4.3 | Стабильность длинного роллаута (длинные горизонты; refiner / коррекция солвером; метрики сохранения) | `[ ]` |
| 4.4 | Обобщение на новые конфигурации (невиданное число/расстановка, массы/материалы) | `[ ]` |
| 4.5 | Рендер динамики и физ-валидация (`PhyWorldBench`/`T2VPhysBench`/`Physion` + собственные чеки) | `[ ]` |
| 4.G | 🚦 Go/No-Go фазы 4 | `[ ]` |

| ID | Задача | Статус |
| -- | ------ | ------ |
| 5.1 | Сшивка конвейера (ассеты → состояние → `fθ` → рендер; типизированные контракты интерфейсов) | `[ ]` |
| 5.2 | Physics-guidance для критичных кадров (дифф-физика/дифф-рендер как ограничение; выборочно) | `[ ]` |

| 5.4 | Сквозная валидация на обеих модальностях (ось A на фото, ось B на видео, человеко-оценка) | `[ ]` |
