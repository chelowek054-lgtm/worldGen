# Эксплуатация

Сборка, развёртывание, эксплуатация. Роль каждой части в архитектуре —
[architecture, раздел 4](../architects/system/architecture.md#4-стек).

> **Состояние:** развёрнут только dev-контур веб-стека. Прод-контур, CI/CD и
> инфраструктура под рендер-воркеры не построены — разделы ниже фиксируют
> требования, а не существующее.

## Что где исполняется

| Часть | Роль | Как запускается |
| ----- | ---- | --------------- |
| `backend/` | сервис сцены: граф, реестр ассетов, очередь заданий | Docker Compose |
| `frontend/` | редактор сцены | Docker Compose |
| `engine/` | воркер: сборка сцены, рендер, перерисовка | пока локально из venv |
| Postgres | граф сцены, реестр, состояния | контейнер, том `pgdata` |
| Redis | очередь заданий на рендер | контейнер |

## Окружения

| Окружение | Назначение | Конфиг |
| --------- | ---------- | ------ |
| development | локальная разработка | `docker-compose.yml` + `docker-compose.override.yml` |
| staging | предпрод, приёмка | не создано |
| production | боевое | не создано |

Базовый и dev-оверрайд не сливать в один файл: `docker-compose.override.yml`
подхватывается автоматически поверх базового.

## Требования к контуру рендера

Того, чего нет в текущем dev-контуре, но потребуется, как только рендер
переедет с локальной машины:

- **GPU-узлы** для перерисовки; профиль потребления пока не измерен.
- **Blender** на воркерах, headless-режим, фиксированная версия — расхождение
  версий ломает воспроизводимость кадра.
- **Асинхронность.** Рендер и симуляция — длительные задания через очередь, а не
  синхронные запросы.
- **Хранилище ассетов и запечённых состояний.** Объём растёт с библиотекой, а не
  с числом кадров.
- **Пиннинг версий ассетов.** Обновление ассета сдвигает всё, что на него
  ссылается, и ретроактивно меняет уже показанные пользователю кадры — см.
  [Roadmap 17.4](../base-plans/Roadmap.md#174-где-консистентность-всё-ещё-течёт).

## Воспроизводимость

Требование движка, которое эксплуатация обязана не сломать: один конфиг → один
прогон → залогированные метрики. Фиксируются seed, версии весов и версия
рендерера; трекинг — MLflow, данные и веса — DVC.

Артефакты прогонов (`engine/runs/`, `mlruns/`) и `engine/data/**` в git не
попадают — см. [engine/.gitignore](../../engine/.gitignore).

## Секреты

`.env` в git не коммитится, шаблон — `.env.example`. Ротация ключей и хранилище
секретов для прод-контура не определены.
